# Хранилище

## Общая идея

Workout Planner хранит пользовательские данные локально в браузере через `localStorage`. Серверного API и синхронизации между устройствами нет.

Ключ хранилища:

```text
workout-tracker:data
```

Текущая версия схемы:

```text
6
```

## Состав store

Корневой объект содержит:

| Поле | Назначение |
| --- | --- |
| `version` | Версия схемы данных. |
| `settings` | Язык, тема, звук, избранное, календарь и последнее открытое. |
| `profile` | Антропометрия, цели, ограничения, восстановление и предпочтения. |
| `equipment` | Выбранное и пользовательское оборудование. |
| `customExercises` | Пользовательские упражнения. |
| `workouts` | Сохраненные тренировки. |
| `history` | История выполненных тренировок. |
| `activeSession` | Снимок активной тренировки для восстановления. |

## Основные файлы

| Файл | Назначение |
| --- | --- |
| `js/storage/schema.js` | Константы схемы, дефолтные значения, разрешенные перечисления. |
| `js/storage/records.js` | Создание, нормализация и валидация записей. |
| `js/storage/store.js` | Низкоуровневое чтение, запись, сброс и инициализация. |
| `js/storage/migrations.js` | Миграции между версиями store. |
| `js/storage/core.js` | Публичный фасад для остального приложения. |
| `js/storage/*Repository.js` | Репозитории по разделам данных. |

## Репозитории

| Репозиторий | Ответственность |
| --- | --- |
| `settingsRepository.js` | Настройки, избранное, пользовательские аудио, последнее открытое. |
| `profileRepository.js` | Профиль, выбранное оборудование, пользовательское оборудование. |
| `workoutRepository.js` | CRUD тренировок, дублирование, сортировка. |
| `historyRepository.js` | CRUD истории и поиск по дате. |
| `sessionRepository.js` | Активная тренировочная сессия. |

## Нормализация

Все сохраняемые данные проходят через санитайзеры в `records.js`. Они:

- приводят строки и даты к ожидаемому виду;
- отбрасывают неизвестные или некорректные enum-значения;
- нормализуют массивы строк;
- задают дефолты для отсутствующих полей;
- ограничивают числовые значения допустимыми диапазонами;
- удаляют невалидную активную сессию.

## Миграции

Миграции выполняются при загрузке store. Если версия старее текущей, `migrateStore()` последовательно применяет переходы до `STORAGE_VERSION`.

Текущие переходы:

- `1 -> 2` - перенос избранного и custom audio в `settings`, миграция старого active session;
- `2 -> 3` - удаление legacy-полей `favorites` и `customAudio` из корня;
- `3 -> 4` - приведение к новой дефолтной форме store;
- `4 -> 5` - миграция legacy-цели профиля в взвешенные `profile.goals`;
- `5 -> 6` - добавление `profile.bodyFocusGoals`.

Если в хранилище лежит версия новее текущей, приложение предупреждает в консоль и применяет санитайзеры без попытки отката.

## Импорт и экспорт

Экспорт создает JSON с метаданными:

- `app: "workout-tracker"`;
- `version`;
- `exportedAt`;
- пользовательские разделы данных.

Экспортируемые разделы:

- `settings`;
- `profile`;
- `equipment`;
- `customExercises`;
- `workouts`;
- `history`.

Импорт поддерживает:

- `merge` - слияние с текущими данными;
- `replace` - замена store с дефолтами для отсутствующих разделов.

Legacy-поля `favorites` и `customAudio` принимаются при импорте и переносятся в `settings`.

## Валидация импорта

Перед импортом проверяется:

- корень JSON должен быть объектом;
- должен присутствовать хотя бы один известный раздел;
- неизвестные разделы отклоняются;
- объектные разделы должны быть объектами;
- списковые разделы должны быть массивами;
- элементы массивов сущностей должны быть объектами;
- custom audio должен содержать известные события и Data URL.

При ошибке выбрасывается `ImportValidationError` с деталями на русском языке.

## Активная сессия

`activeSession` сохраняет только восстановимую часть текущей тренировки:

- версию снимка;
- время сохранения;
- статус `running` или `paused`;
- нормализованную тренировку;
- список ID шагов и их длительности;
- текущий индекс шага;
- оставшееся и прошедшее время;
- время старта.

Завершенная или прерванная тренировка удаляет снимок.

## Конфиденциальность

Данные остаются в браузере пользователя. При очистке данных сайта, смене домена или браузера они будут недоступны, если заранее не сделать экспорт.
