# PWA и офлайн-режим

## Компоненты PWA

PWA-часть состоит из:

- `manifest.webmanifest` - имя, иконки, режим отображения, shortcuts;
- `sw.js` - service worker и cache-first логика;
- `js/core/pwa.js` - регистрация service worker;
- `scripts/generate-precache.js` - генерация app shell precache.

## Manifest

Приложение объявлено как `Workout Planner`, короткое имя - `Workout`. Режим отображения - `standalone`, ориентация - `portrait-primary`.

В manifest указаны:

- PNG и SVG-иконки;
- theme и background colors;
- категории `fitness`, `health`, `productivity`;
- shortcuts на каталог упражнений и создание тренировки.

## Service worker

`sw.js` использует кеш с ревизией в имени:

```text
workout-planner-<hash>
```

В `APP_SHELL` перечислены файлы, необходимые для запуска приложения:

- корневой путь и `index.html`;
- иконки;
- JS-модули;
- CSS;
- manifest.

## Жизненный цикл кеша

`install`:

- открывает текущий кеш;
- добавляет все файлы `APP_SHELL`;
- вызывает `skipWaiting()`.

`activate`:

- удаляет старые кеши с другим именем;
- вызывает `clients.claim()`.

`fetch`:

- пропускает не-GET запросы;
- для навигации пытается получить сеть и обновить `index.html` в кеше;
- при ошибке навигации возвращает закешированный `index.html`;
- для остальных GET-запросов сначала ищет кеш, затем сеть;
- успешные сетевые ответы дополнительно кладет в кеш.

## Обновление precache

После изменения статических импортов, CSS, manifest, иконок, `index.html` или generated exercise data выполните:

```bash
npm run generate:precache
```

Скрипт обновляет список `APP_SHELL` и имя кеша в `sw.js`.

Затем проверьте:

```bash
npm test -- tests/pwa/service-worker.test.js
```

Тест проверяет, что precache покрывает локальные статические ES-импорты, нужные для app shell.

## Ограничения офлайн-режима

Офлайн-режим покрывает статические файлы приложения. Пользовательские данные находятся в `localStorage` и не требуют сети.

Ограничения:

- первый запуск должен пройти онлайн;
- service worker не работает при открытии через `file://`;
- данные не синхронизируются между устройствами;
- очистка данных сайта удалит пользовательские тренировки, профиль и историю;
- обновление service worker зависит от политики браузера и может потребовать перезагрузки страницы.

## Проверка вручную

1. Запустите приложение через локальный сервер.
2. Откройте DevTools и убедитесь, что service worker зарегистрирован.
3. Перезагрузите страницу.
4. Включите offline-режим в DevTools.
5. Перейдите на основные маршруты: `#home`, `#exercises`, `#settings`.
6. Убедитесь, что app shell загружается без сети.

## Когда нужно менять service worker

Меняйте или регенерируйте `sw.js`, если:

- добавлен новый статический модуль, который импортируется приложением;
- изменена структура CSS-файлов;
- добавлены новые иконки или assets, нужные при старте;
- изменен `manifest.webmanifest`;
- изменен алгоритм кеширования.
