# Архитектура

## Общая модель

Workout Planner - локальное browser-first приложение. Сервер нужен только для отдачи статических файлов. Бизнес-логика, состояние, хранение данных, рекомендации и тренировочная сессия выполняются в браузере.

Основные свойства:

- нет фронтенд-фреймворка;
- нет серверного API;
- маршрутизация через hash;
- состояние приложения хранится в JS-модулях и `localStorage`;
- офлайн-запуск обеспечивается service worker.

## Слои

```text
index.html
  ↓
js/app.js
  ↓
core: router, state, pwa, selectors, utils
  ↓
ui: shell, event bindings, actions
  ↓
pages: renderers
  ↓
features / session / storage
```

## Bootstrap

Точка входа - `js/app.js`.

Порядок запуска:

1. регистрация service worker;
2. инициализация shell-интерфейса;
3. подписка рендера на состояние;
4. загрузка встроенных упражнений;
5. запуск роутера.

Такой порядок гарантирует, что роутер выберет активный экран после загрузки данных упражнений.

## Роутинг

Роутер находится в `js/core/router.js`. Он читает `window.location.hash`, нормализует route и параметры, затем записывает их в состояние.

Поддерживаемые маршруты:

| Route | Экран |
| --- | --- |
| `#home` | Главная. |
| `#exercises` | Каталог упражнений. |
| `#recommendations` | Рекомендации. |
| `#exercise-create` | Создание упражнения. |
| `#exercise-view/<id>` | Просмотр упражнения. |
| `#exercise-edit/<id>` | Редактирование пользовательского упражнения. |
| `#workout-create` | Конструктор тренировки. |
| `#workout-generate` | Генератор тренировки. |
| `#workout-view` | Список тренировок. |
| `#workout-view/<id>` | Детали тренировки. |
| `#workout-edit/<id>` | Редактирование тренировки. |
| `#workout-run/<id>` | Активная сессия. |
| `#settings` | Настройки. |

## Состояние и рендеринг

Глобальное состояние находится в `js/core/state.js`. UI подписывается на изменения через `subscribe(renderApp)`. Рендереры страниц находятся в `js/pages/`, а shell и события - в `js/ui/`.

Практическое правило: рендереры строят HTML, UI-actions меняют состояние или вызывают доменные функции, а доменные модули не зависят от DOM.

## Доменный слой

`js/features/` содержит бизнес-логику:

| Модуль | Ответственность |
| --- | --- |
| `exercises.js` | Загрузка и нормализация встроенных и пользовательских упражнений. |
| `equipment.js` | Каталог оборудования. |
| `contraindications.js` | Нормализация противопоказаний и связанных сигналов. |
| `exercise-compatibility.js` | Совместимость с оборудованием и уровнем профиля. |
| `recommendations.js` | Фильтрация и скоринг упражнений. |
| `workout-generation.js` | Генерация одной тренировки. |
| `workouts.js` | Нормализация тренировок, расчет длительности и калорий. |
| `history.js` | История, календарные данные и агрегаты. |
| `audio.js` | Звуковые сигналы и пользовательские аудиофайлы. |

## Хранилище

`js/storage/` реализует local-first слой:

- `schema.js` - версии, дефолты, разрешенные значения;
- `records.js` - фабрики и санитайзеры записей;
- `migrations.js` - миграции между версиями;
- `store.js` - чтение и запись `localStorage`;
- `*Repository.js` - операции по доменным областям;
- `core.js` - публичный фасад.

Приложение хранит данные под ключом `workout-tracker:data`.

## Движок сессии

`js/session/` отвечает за активную тренировку:

- `steps.js` превращает тренировку в последовательность упражнений и отдыхов;
- `core.js` управляет таймером, статусами, фазами и хуками;
- `snapshot.js` сохраняет и восстанавливает активную сессию;
- `ui.js` и `ui-format.js` форматируют состояние для интерфейса.

Движок не привязан к конкретному экрану и покрыт отдельными тестами.

## Поток генерации тренировки

1. Пользователь задает длительность, тип и приоритеты.
2. `workout-generation.js` нормализует запрос.
3. `recommendations.js` фильтрует и ранжирует упражнения.
4. Генератор строит шаблон слотов.
5. Для каждого слота выбирается уникальное упражнение.
6. Назначаются подходы, повторы или длительность и отдых.
7. Объем подгоняется к целевой длительности.
8. Результат сохраняется как обычная тренировка.

## Международные тексты

Файлы локализации находятся в `js/i18n/`. Поддерживаются русский и английский языки. При добавлении пользовательских строк нужно обновлять оба файла сообщений.

## Границы ответственности

- `features` не должен знать о DOM.
- `pages` не должен напрямую реализовывать сложную бизнес-логику.
- `ui` связывает события пользователя с действиями и состоянием.
- `storage` владеет формой сохраняемых данных.
- `session` владеет логикой таймера и восстановления активной тренировки.
